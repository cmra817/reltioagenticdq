# Project architecture decisions

- `AddDatasetModal` owns the shared three-step data-asset workflow and supports fullscreen or app-shell presentation, so regular and agentic entry points cannot drift.
- `SetupSessionProvider` (add-dataset-agentic/setup-sessions) owns in-progress agentic setups in localStorage and their open/close state, so navigating away never loses a plan.
- `DomainProvider` owns the selected domain and saves it to localStorage, applied after hydration so server and client render the same first frame. Domain health scores come from `healthFor`, which is a mock standing in for the metric layer; `statusForScore` is the single place that turns a score into good, warn, or bad.
- A chat's `domain` tag is set when the chat is created and is never rewritten, so a chat that later moves focus does not hop between domains in the sidebar. Pinning only applies to chats (never dashboards) and does not change `updatedAt`.
- The sidebar is three zones: global destinations (Search, Data health, Scheduled, Rules), a scrolling region (Pinned, Domains, Recents), and the footer. Domains sort by lowest health first so the ones that need attention are on top. Chat threads live only under Recents (or Pinned), never expanded under a domain; a thread's domain tag is just a label on its Recents row.
- Schedules, runs, rules, and dashboards share one mock layer (`lib/mock-ops.ts`) and one localStorage store (`lib/ops-store.ts`, built on `useLocalStore`). A schedule is the job definition; a run is one execution of it. A rule is the shared library definition; a check is a rule a schedule applies to a table.
- Sub-views of Scheduled and Rules (schedule, run, rule, new rule) are search params on `/scheduled` and `/rules`, not separate routes. `/domain?table=` is the domain home, and opening a table keeps the same chat and swaps the right panel.
- Editing a rule that schedules use always goes through the impact check (everywhere, save as new, or some schedules). Only runs that failed or need attention, and have not been opened, reach Recents.
- Explore and DQ checks are no longer under domains in the sidebar; the domain page's Tables and Checks tabs replace them. The old pages remain reachable from search (Cmd/Ctrl+K).
- The schedule detail page is one page (shared header, run history left, `PlanView` in `bare` mode right, no chat) with `scheduleToPlan`/`planToSchedule` adapters and inline edits, so schedules and the add-asset plan never drift.
