# Architecture decisions

- Opening a schedule is a chat thread (kind `schedule`, route `/schedule/$threadId`, thread id `schedule-view-<scheduleId>`, one per schedule, state in `agentflow.schedule-threads.v2`), built like the rule and dashboard threads: 59vw right panel, hide/show chat, floating prompt. A schedule opens with the chat on the left and the page on the right; opening it sends "Tell me about the … task" automatically (unless a run is in focus), so it joins Recents at once. A run is described only when opened or asked about. The panel has Insights (runs passed, last/next run, checks-passing trend, top failing table and rule bars, tables and rules, click a rule to open its thread), Plan (`PlanView` in `bare` mode with `scheduleToPlan`/`planToSchedule`, always editable) and Runs (list, then a run's results inside the panel). Opening a run, from anywhere (Runs list, Insights, a Recents alert), sends the question "Tell me more about the … run …" for the person and the agent answers; the run opens in the panel at the same time. Run now and Pause/Resume are icon buttons in the panel header; chat can also run, pause, resume, change timing (`parseSchedule`), and add or remove rules. A failed-run alert in Recents opens that schedule's thread with the run in focus (`?run=`). Old `/scheduled?schedule=` and `?run=` links redirect to the thread. The Scheduled list page (Schedules and Runs tabs) remains the index.
- "+ New task" opens the agentic setup with purpose "task": it auto-sends the request, asks for a domain when the Tasks filter is All domains, asks for tables/checks/cadence, then drafts the plan; Save task adds a Schedule (with its plan) to ops-store and opens its chat.
