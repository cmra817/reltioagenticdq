# Architecture decisions

- There is one chat page: `/domain`. "New chat" opens `/domain?all=true&n=<id>`, a domain's plus opens `/domain?n=<id>`; `n` forces a fresh chat and `q` sends a seed prompt. `/chat/$chatId` only redirects (migrating older chats into `agentflow.domain-chats.v1`). An empty chat centers its intro and prompt box (`ScopedChat` `centerWhenEmpty`).
- The domain page (`/domain`, `domain/domain-screen.tsx`) is chat-first and matches the approved prototype. Chat header is "Chat" plus a scope tag; chips "Which tables are late?" and "Show me the projects". Above the prompt box sit a Scope select (a domain or All domains via `?all=true`; locks after the first message; a new scope remounts the whole screen as a new chat) and a Project select (hidden for All domains; picking one posts an agent message with an "Open the project" link and answers from `projectReply`). The right panel starts minimized (`domain/domain-rail.tsx`): "{domain} brief" (about the domain, same for everyone, not customizable), a clickable score tile with trend, clickable lowest-three table bars, and rows into Tables and Projects. Expand opens Overview (brief, four clickable stat tiles, 14-day trend, health by table), Tables (search, health, updated, project badge; a table opens Overview, Columns, Sample data, Events, Checks), Checks (kept from before, not in the prototype) and a Projects link. Every line, tile, chart and bar sends "Let's discuss: <topic>" into the chat; answers can carry bars, a trend or a link button (`ChatVisual` kind `link`). The brief at domain level is different from a dashboard's "My brief", which is written from that dashboard's own instructions and schedule.
- A chat on `/domain` is saved as a thread of kind `domain` the moment its first message is sent, tagged with its scope domain (none for All domains), so Recents nests it under that domain. Its turns, scope and project are in `agentflow.domain-chats.v1`; Recents reopens it at `/domain?thread=<id>`.
